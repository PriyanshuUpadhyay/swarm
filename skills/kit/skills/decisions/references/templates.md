# Decision record templates

Three tiers, one shared frontmatter. Lifted from MADR (`adr.github.io/madr`), Nygard
(2011), Y-statements (Zimmermann). Pick the lowest tier that fits — ceremony is a cost.

## Tier selection (decided at write time, not at capture)
The capture gate (does it reach the buffer?) is separate: capture anything with a real
alternative, plus all reversals. The **tier** is chosen when writing the record:
| Tier | Use when | Stored as |
|---|---|---|
| 1 — Y-statement | Cheap to reverse AND localized | `NNNN-title.md` (tiny stub) |
| 2 — MADR-minimal | Significant **OR** non-localized | `NNNN-title.md` |
| 3 — MADR-full | Costly-to-reverse **AND** non-localized | `NNNN-title.md` |

Every tier is a numbered file — so the index is *fully* re-derivable from files (no
record lives only in the generated index).

## Shared frontmatter (all records, every tier)
```yaml
---
status: accepted          # proposed | accepted | superseded
date: 2026-06-01          # YYYY-MM-DD, the day it was decided
deciders: []              # optional — names/roles
supersedes:               # optional — NNNN this record reverses
superseded-by:            # optional — NNNN that later reversed this (written reciprocally)
related: []               # optional — NNNN(s) this decision connects to (non-supersede)
informed-by: []           # optional — sources that drove it: files / docs / data / links
links: []                 # optional (Tier-3) — commits / PRs / issues / files
---
```
Supersession is encoded **once**: `status: superseded` + the target in `superseded-by`.
(No `superseded-by-NNNN` baked into status — that would duplicate the link and risk desync.)

## Tier 1 — Y-statement stub
A full file with frontmatter and a single Y-statement line. The two negative clauses are
**mandatory** (they prevent pros-only ADRs):
```markdown
# NNNN. <short title>

In the context of <use-case/component>, facing <concern>, we chose <option> and
neglected <alternatives>, to achieve <benefit>, accepting that <downside>.
```
A stub is still a numbered file, so it carries `related`/supersede links like any record.

## Tier 2 — MADR-minimal (default)
```markdown
# NNNN. <Title — names the problem and the chosen solution>

## Context and Problem Statement
<1–2 short paragraphs. The forces at play, stated value-neutrally.>

## Considered Options
- <option A>
- <option B>
<≥2 real options — no straw-man "Dummy Alternative".>

## Decision Outcome
Chosen: <option>, because <rationale>.

### Consequences
- Good: <what becomes easier>
- Bad: <what becomes harder>
<Both Good AND Bad are required.>
```

## Tier 3 — MADR-full
Tier 2, plus these sections after `Decision Outcome`:
```markdown
## Decision Drivers
- <driver / constraint 1>
- <driver / constraint 2>

## Pros and Cons of the Options
### <option A>
- Good, because <…>
- Neutral, because <…>
- Bad, because <…>
### <option B>
- Good, because <…>
- Bad, because <…>

## Confirmation
<The fitness function: the test, review, or metric that verifies this decision still
holds. E.g. "CI asserts p99 < 200ms" or "revisit at 10k RPS".>

## Informed by
<The audit trail: which files / docs / data / prior decisions drove this choice — so a
future reader can reconstruct what evidence the decision rested on.>

## Links
- Supersedes / superseded by: <NNNN>
- Related: <NNNN — other decisions this connects to>
- Sources: <commits / PRs / issues / files>
```

## Pre-finalize checklist (run before saving any record)
Encodes Zimmermann's ADR anti-patterns. If any fails, fix or re-elicit first. For a Tier-1
stub, the mandatory "neglected <alternatives>" and "accepting that <downside>" clauses
satisfy the alternative + downside checks inline.
- [ ] **Not a Fairy Tale** — has ≥1 genuine downside (Bad / "accepting that…").
- [ ] **No Dummy Alternative** — Considered Options are real, not straw men.
- [ ] **Not a Maze** — title matches the content; one decision, not several tangled.
- [ ] **Not a Mega-ADR** — fits roughly on one page.
- [ ] **Active voice** — "We chose…", not "It was decided…".
- [ ] **Frontmatter complete** — status + date set; reversal links reciprocal if applicable.

## README.md index format
Fully derived from the record files, newest first. Every record (all tiers) has a row.
```markdown
# Decision records

ADR format. Read this index before proposing changes. Record bodies are immutable —
reversals supersede, never edit. Fully generated by the `decisions` skill; do not hand-edit.

| #    | Title                        | Tier | Status     | Date       | Refs  |
|------|------------------------------|------|------------|------------|-------|
| 0003 | Drop Redis cache layer       | 2    | accepted   | 2026-06-01 | ↑0001 |
| 0002 | Pino over winston for logs   | 1    | accepted   | 2026-06-01 |       |
| 0001 | Add Redis cache layer        | 2    | superseded | 2026-05-30 | ~0003 |
```
`Refs` is a compact relationship view (the lightweight "graph"): `↑NNNN` supersedes,
`~NNNN` superseded-by, `→NNNN` related. All columns derived from frontmatter / filename.
