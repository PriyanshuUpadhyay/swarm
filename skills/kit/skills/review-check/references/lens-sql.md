# SQL lens

These rules add checks for SQL queries, schemas, and migrations in SQL files and in code that builds SQL.

Files: `**/*.{sql,ts,tsx,js,mjs,py,go,rs,java,kt,rb}`

- `SQL-3` A function, cast, or arithmetic wrapped around a column in `WHERE`, `JOIN ON`, or `ORDER BY` (`lower(email) = ?`, `date(created_at) = ?`, `CAST(id AS TEXT) = ?`, `json_extract(data,'$.x') = ?`) → move the transform to the constant side (`created_at >= ? AND created_at < ?`), or add an expression index that matches the expression exactly. Applies: `(?i)\b(WHERE|AND|OR|ON|ORDER\s+BY)\b[^;]*\b(lower|upper|date|datetime|strftime|julianday|unixepoch|substr|substring|trim|coalesce|ifnull|cast|json_extract|abs|round|to_char|date_trunc)\s*\(`. Source: https://www.sqlite.org/optoverview.html#where_clause_analysis (a term is index-usable only in the forms `column op expr`; an index on an expression matches only that expression); https://www.postgresql.org/docs/current/indexes-expressional.html
- `SQL-4` `LIKE`/`GLOB`/`ILIKE` with a leading wildcard (`'%' || ?`, a pattern built as `` `%${q}%` ``), or a `LIKE` prefix search on a column whose collation does not match `case_sensitive_like` → full-text index (FTS5, `tsvector`/`pg_trgm`) or a true prefix pattern on a matching collation; if a scan is accepted, say it is bounded (`engineering-standards` P2). Applies: `(?i)\b(I?LIKE|GLOB)\b`. Source: https://www.sqlite.org/optoverview.html#the_like_optimization (index use needs a literal prefix without a leading wildcard and a matching collation)
- `SQL-5` A new or changed `WHERE`/`JOIN`/`ORDER BY`/`GROUP BY` on a hot path whose columns no index serves with equality columns leftmost and at most one trailing range column → name the index that serves it, or add one; `EXPLAIN QUERY PLAN` shows `SEARCH ... USING INDEX` and no `USE TEMP B-TREE FOR ORDER BY`. Sharpens `engineering-standards` P2 and D1. Applies: `(?i)\b(WHERE|JOIN|ORDER\s+BY|GROUP\s+BY)\b`. Source: https://www.sqlite.org/optoverview.html#where_clause_analysis (leftmost-column rule; columns after a gap or an inequality are not used); https://www.sqlite.org/eqp.html
- `SQL-6` `UPDATE` or `DELETE` with no `WHERE`, or a `WHERE` that does not include the tenant or owner key the rest of the function scopes by → add the key; a missing tenant filter is both a data-loss and an authorization defect (see SRV-1). Applies: `(?i)\b(UPDATE\s+\w+\s+SET|DELETE\s+FROM)\b`. Source: https://www.sqlite.org/lang_delete.html ("If the WHERE clause is omitted ... all records in the table are deleted"); https://www.sqlite.org/lang_update.html
- `SQL-8` A transaction at `REPEATABLE READ` or `SERIALIZABLE`, or any transaction that can deadlock, with no retry on SQLSTATE `40001`/`40P01` → retry the whole transaction from `BEGIN` with a bounded, jittered budget (`engineering-standards` R3); never retry only the failed statement. Applies: `(?i)(SERIALIZABLE|REPEATABLE\s+READ|isolation_?level|40001|40P01)`. Source: https://www.postgresql.org/docs/current/mvcc-serialization-failure-handling.html (applications must retry the complete transaction on serialization failure)
- `SQL-9` SQLite `BEGIN` (deferred) in a transaction that reads first and writes later, on a database that other connections also write → `BEGIN IMMEDIATE`, so the write lock is taken up front and the upgrade cannot fail with `SQLITE_BUSY` mid-transaction. Not for a Durable Object (one connection; see CF-12). Applies: `(?i)\bBEGIN(\s+DEFERRED)?(\s+TRANSACTION)?\s*[;'"\x60)]`. Source: https://www.sqlite.org/lang_transaction.html#deferred_immediate_and_exclusive_transactions (a read transaction that upgrades to write can get SQLITE_BUSY)
- `SQL-10` A network call, LLM call, or `sleep` inside an open database transaction → do the slow I/O before `BEGIN` or after `COMMIT`; the transaction holds row locks (Postgres) or the single writer lock (SQLite) for the whole call. Files: `**/*.{ts,tsx,js,mjs,py,go,rs,java,kt,rb}`. Applies: `(?i)(transaction|BEGIN|\.tx\b|atomic)`. Source: https://www.postgresql.org/docs/current/runtime-config-client.html#GUC-IDLE-IN-TRANSACTION-SESSION-TIMEOUT (an open transaction holds locks and prevents vacuum); https://www.sqlite.org/lang_transaction.html (one write transaction at a time)
- `SQL-11` Postgres `CREATE INDEX` / `CREATE UNIQUE INDEX` on an existing table without `CONCURRENTLY`, or `CONCURRENTLY` inside a migration that the tool wraps in a transaction, or no plan for the `INVALID` index a failed concurrent build leaves → `CREATE INDEX CONCURRENTLY` outside a transaction block, and `DROP INDEX CONCURRENTLY IF EXISTS` before a retry. Files: `**/{migrations,migration,migrate,db,schema}/**`. Applies: `(?i)CREATE\s+(UNIQUE\s+)?INDEX\b`. Source: https://www.postgresql.org/docs/current/sql-createindex.html#SQL-CREATEINDEX-CONCURRENTLY (plain build blocks writes; concurrent build cannot run in a transaction block; a failed one leaves an invalid index that still costs writes)
- `SQL-13` SQLite `ALTER TABLE ... ADD COLUMN` with `PRIMARY KEY`, `UNIQUE`, `NOT NULL` and no non-null default, a `CURRENT_TIMESTAMP`/`CURRENT_TIME`/`CURRENT_DATE` or parenthesized expression default, a `STORED` generated column, or `REFERENCES` with a non-null default → the statement fails at migrate time; add a nullable column or a constant default, or do a table rebuild. Applies: `(?i)ALTER\s+TABLE\s+\S+\s+ADD\b`. Source: https://www.sqlite.org/lang_altertable.html#alter_table_add_column
- `SQL-16` A new `REFERENCES` / `FOREIGN KEY` in Postgres with no index on the referencing columns → add one; Postgres does not create it, so each parent `DELETE`/key `UPDATE` scans the child. Extends `engineering-standards` D1 (SQLite) to Postgres. Applies: `(?i)(REFERENCES|FOREIGN\s+KEY)`. Source: https://www.postgresql.org/docs/current/ddl-constraints.html#DDL-CONSTRAINTS-FK ("a declaration of a foreign key constraint does not automatically create an index on the referencing columns")
- `SQL-17` Code that relies on `ON DELETE CASCADE`, `SET NULL`, or FK rejection in plain SQLite without `PRAGMA foreign_keys = ON` on that connection, or that sets the pragma inside a transaction → enable it per connection outside a transaction, or confirm the host engine enforces FKs by default. Applies: `(?i)(REFERENCES|FOREIGN\s+KEY|ON\s+DELETE|foreign_keys)`. Source: https://www.sqlite.org/foreignkeys.html#fk_enable (off by default; per connection; a no-op inside a transaction)
- `SQL-18` An `IN (...)` list or multi-row `VALUES` whose placeholder count grows with an input array → chunk to the engine's bound-parameter limit (SQLite default 32766; Durable Object SQLite and D1 100), or use `json_each(?)`/`unnest($1)` with one parameter. Applies: `(?i)(\bIN\s*\(|\bVALUES\b)`. Source: https://www.sqlite.org/limits.html#max_variable_number; https://developers.cloudflare.com/durable-objects/platform/limits/ ("Maximum bound parameters per query: 100")
- `SQL-19` A SQL string built by concatenation, template interpolation, `%`/`.format`/f-string with any value not a compile-time constant → bound parameters for values; an allowlist map for identifiers and sort directions. Files: `**/*.{ts,tsx,js,mjs,py,go,rs,java,kt,rb}`. Applies: `(?i)\b(SELECT|INSERT|UPDATE|DELETE|WHERE|ORDER\s+BY)\b.*(\$\{|["'\x60]\s*\+|\+\s*["'\x60]|%s|\{\w*\}|\.format\(|f["'])`. Source: https://cheatsheetseries.owasp.org/cheatsheets/SQL_Injection_Prevention_Cheat_Sheet.html (primary defense: prepared statements; allowlist for identifiers)
- `SQL-20` `NOT IN (SELECT col ...)` where `col` can be NULL → `NOT EXISTS (SELECT 1 ... WHERE ...)`; one NULL makes `NOT IN` return no rows. Applies: `(?i)NOT\s+IN\s*\(\s*SELECT`. Source: https://www.postgresql.org/docs/current/functions-subquery.html#FUNCTIONS-SUBQUERY-NOTIN (if a right-hand row is null, the result of NOT IN is null, not true)
- `SQL-21` A `UNIQUE` constraint or index meant to allow one row per key where a key column is nullable → `NOT NULL` on the column, a sentinel, or Postgres `NULLS NOT DISTINCT`; NULLs are distinct, so duplicates pass. Applies: `(?i)\bUNIQUE\b`. Source: https://www.sqlite.org/lang_createtable.html#unique_constraints ("NULL values are considered distinct from all other values"); https://www.postgresql.org/docs/current/ddl-constraints.html#DDL-CONSTRAINTS-UNIQUE-CONSTRAINTS
- `SQL-22` `INSERT OR REPLACE` / `REPLACE INTO` used as an update, or `ON CONFLICT (cols)` whose columns are not exactly a unique index or primary key → `INSERT ... ON CONFLICT (<unique key>) DO UPDATE SET` naming the columns to change; REPLACE deletes the old row, so unlisted columns reset, delete triggers and cascades fire, and the rowid changes. Applies: `(?i)(OR\s+REPLACE|REPLACE\s+INTO|ON\s+CONFLICT)`. Source: https://www.sqlite.org/lang_conflict.html (REPLACE "deletes pre-existing rows"); https://www.sqlite.org/lang_upsert.html (the conflict target must match a uniqueness constraint)
- `SQL-23` An `INTEGER PRIMARY KEY` (rowid) used as an external or long-lived id (in URLs, cursors, other tables, caches) on a table whose rows are deleted, without `AUTOINCREMENT` → `AUTOINCREMENT` or a separate stable id; SQLite may reuse the largest deleted rowid. Applies: `(?i)INTEGER\s+PRIMARY\s+KEY`. Source: https://www.sqlite.org/autoinc.html (without AUTOINCREMENT, rowids of deleted rows may be reused)
- `SQL-24` Time values compared or sorted as text when two formats can meet (SQLite `datetime()`/`CURRENT_TIMESTAMP` give `YYYY-MM-DD HH:MM:SS`; JS `toISOString()` gives `YYYY-MM-DDTHH:MM:SS.sssZ`), or a column that mixes seconds and milliseconds → one stored format and unit per column, converted at the boundary. Applies: `(?i)(datetime\(|date\(|strftime|julianday|unixepoch|CURRENT_TIMESTAMP|toISOString|Date\.now|_at\b)`. Source: https://www.sqlite.org/lang_datefunc.html (format of datetime(); SQLite has no date type); https://www.sqlite.org/datatype3.html#comparisons
- `SQL-25` A new SQLite table without `STRICT` whose columns are compared against bound values of another type (numbers bound as text, ids as strings) → `STRICT`, or bind the declared type; affinity rules make `'12' = 12` depend on column affinity and can skip the index. Applies: `(?i)CREATE\s+TABLE`. Source: https://www.sqlite.org/stricttables.html; https://www.sqlite.org/datatype3.html#type_affinity_of_comparison_operands
- `SQL-26` (web) A data backfill (`UPDATE` over existing rows, `update_all`, `INSERT ... SELECT`) in the same migration or transaction as a schema change → a separate migration, run in batches outside the DDL transaction; the table lock lasts as long as the backfill. Migration linters cannot detect this. Files: `**/{migrations,migration,migrate,db,schema}/**`. Applies: `(?i)(UPDATE\s+\w+\s+SET|update_all|INSERT\s+INTO\s+\S+.*SELECT)`. Source: https://github.com/ankane/strong_migrations#backfilling-data; https://gocardless.com/blog/zero-downtime-postgres-migrations-the-hard-parts/. Confidence: high.
- `SQL-27` (web) A new Postgres or MySQL primary key or foreign key column typed `int`, `integer`, or `serial` on a table that grows with user activity → `bigint` (`bigserial` or a bigint identity). A 32-bit key runs out after about 2.1 billion ids, and the fix is a long table rewrite. Not for SQLite, whose `INTEGER PRIMARY KEY` is already 64-bit. Applies: `(?i)\bserial\b|\b(int|int4|integer)\b[^,]*(PRIMARY\s+KEY|REFERENCES)`. Source: https://squawkhq.com/docs/prefer-bigint-over-int; https://github.com/danluu/post-mortems (a 2021 outage from an INT32 foreign key reaching its max). Confidence: high.
