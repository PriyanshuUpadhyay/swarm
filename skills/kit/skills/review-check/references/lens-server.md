# Server lens

These rules add checks for HTTP and RPC server handlers and their wire contracts.

Files: `**/*.{ts,tsx,js,mjs,cjs,py,go,rs,java,kt,rb}`

- `SRV-1` A handler that reads, updates, or deletes an object by an id from the path, query, or body, and does not constrain the lookup by the caller's identity or tenant from the auth context → put the owner/tenant key in the query (`WHERE id = ? AND owner_id = ?`) or check access before use; return 404 for a foreign id. Applies: `(?i)(params|query|body|req|request|args|input)\W{1,3}\w*_?id\b`. Source: https://api-security.owasp.org/editions/2023/en/0xa1-broken-object-level-authorization/ (implement an authorization check in every function that accesses a data source using an input from the user)
- `SRV-2` A new route or RPC method without the auth middleware, role check, or decorator that its sibling routes carry, or an admin/internal operation reachable from the public router → the same guard as siblings, or say why it is public. Applies: `(?i)(\.(get|post|put|patch|delete|all|route)\s*\(|@(app|router)\.|@(Get|Post|Put|Patch|Delete)|HandleFunc|rpc\s+\w+\s*\()`. Source: https://api-security.owasp.org/editions/2023/en/0xa5-broken-function-level-authorization/
- `SRV-3` A request body spread or passed whole into a create/update (`{...body}`, `Object.assign(row, body)`, `Model(**data)`, `update(req.body)`) → an explicit allowlist of writable fields; owner, role, plan, and ids never come from the body. Applies: `(?i)(\.\.\.\s*(req\.)?(body|input|data|payload|params)|Object\.assign\(|\*\*(body|data|payload|request)|\.update\(\s*(req\.)?body)`. Source: https://api-security.owasp.org/editions/2023/en/0xa3-broken-object-property-level-authorization/ (mass assignment)
- `SRV-4` A response that serializes a whole storage row or domain object (`return row`, `c.json(user)`) → an explicit response shape; a new column then does not leak or change the wire. Applies: `(?i)(\.json\(|Response\.json|res\.(json|send)\(|jsonify|return\s+\w+\s*;?\s*$)`. Source: https://api-security.owasp.org/editions/2023/en/0xa3-broken-object-property-level-authorization/ (return only the properties the client needs)
- `SRV-6` Pagination, a default limit, or a new filter default added to an existing unpaged list method → a new method or version; old clients read the first page as the whole list. Applies: `(?i)(page_?size|limit|page_?token|cursor|next_?page)`. Source: https://google.aip.dev/158 ("adding pagination to an existing method is a backwards-incompatible change")
- `SRV-8` A protobuf field number reused or changed, or a field deleted without `reserved` for its number and name → reserve both. Files: `**/*.proto`. Source: https://protobuf.dev/programming-guides/proto3/#deleting (you must reserve the deleted number; reuse can cause parse errors, PII leaks, and data corruption)
- `SRV-10` A `GET` or `HEAD` handler that creates, updates, deletes, sends, or charges → move the side effect to `POST`/`PUT`/`DELETE`; crawlers, prefetchers, caches, and automatic retries send safe methods freely. Applies: `(?i)(\.(get|head)\s*\(|@(Get|Head)|methods?\s*[=:]\s*\[?["']GET|http\.MethodGet)`. Source: https://www.rfc-editor.org/rfc/rfc9110#section-9.2.1 (safe methods: the client does not request and does not expect any state change)
- `SRV-11` A `PUT` or `DELETE` handler whose second identical call does something different (appends, increments, sends again, returns 5xx for an already-deleted resource), or a `POST` that clients or infra retry with no idempotency key → make `PUT`/`DELETE` idempotent; a key for `POST` (`engineering-standards` R2). Applies: `(?i)(\.(put|delete|post|patch)\s*\(|@(Put|Delete|Post|Patch)|Method(Put|Delete|Post|Patch))`. Source: https://www.rfc-editor.org/rfc/rfc9110#section-9.2.2 (PUT and DELETE are idempotent; clients may retry them automatically)
- `SRV-12` An idempotency key that is stored after the side effect, not in the same transaction, not scoped to the caller, or reused with a different payload without an error → reserve the key and the result atomically, scope by principal, reject a payload mismatch (422) and a concurrent duplicate (409). Sharpens `engineering-standards` R2. Applies: `(?i)idempoten`. Source: https://datatracker.ietf.org/doc/draft-ietf-httpapi-idempotency-key-header/ (422 for key reuse with a different payload; 409 while the first request is still processing)
- `SRV-13` A full-resource `PUT`/`PATCH` that overwrites stored state with no version or ETag check where two clients can edit the same resource → `If-Match` with the ETag, or a `version` column in the `UPDATE ... WHERE`, and 412 on mismatch. Applies: `(?i)(\.(put|patch)\s*\(|@(Put|Patch)|UPDATE\s+\w+\s+SET)`. Source: https://www.rfc-editor.org/rfc/rfc9110#section-13.1.1 (If-Match prevents the "lost update" problem); https://google.aip.dev/154
- `SRV-14` A status code that misstates the cause: every error mapped to 500, a validation or not-found failure returned as 500, an internal failure returned as 4xx, an error returned as 200 with an error body, or 429/503 without `Retry-After` → 4xx only for a request the client must change, 5xx for server faults, 429/503 with `Retry-After`; clients and retry layers decide on this code. Applies: `(?i)(status\s*[:=(]|\.status\(|HTTPException|raise|throw|catch|except|codes\.)`. Source: https://www.rfc-editor.org/rfc/rfc9110#section-15.5 and https://www.rfc-editor.org/rfc/rfc9110#section-15.6; https://www.rfc-editor.org/rfc/rfc9110#section-10.2.3; https://www.rfc-editor.org/rfc/rfc6585#section-4
- `SRV-15` An error `reason`/`code` string that clients branch on is renamed, reused for a different cause, or removed, or a message that clients parse changes → keep one stable machine code per cause; add a new code for a new cause. Applies: `(?i)(code|reason|error_?type|errorCode)\s*[:=]`. Source: https://google.aip.dev/193 (services must use the same (reason, domain) for the same error and must not reuse it for a different one)
- `SRV-16` An error body that carries a stack trace, SQL text, upstream response body, or internal host names → a stable code and a user-safe message; log the detail. Applies: `(?i)(\.stack|err(or)?\.message|traceback|format_exc|String\(e(rr)?\)|str\(e\)|%v)`. Source: https://api-security.owasp.org/editions/2023/en/0xa8-security-misconfiguration/ (error messages include stack traces or expose other sensitive information); https://google.aip.dev/193 (messages do not assume knowledge of the implementation)
- `SRV-17` A retry wrapped around a call that a lower layer (client library, platform, queue) already retries, or a retry on a non-retryable error (4xx other than 408/429, an "overloaded" signal) → retry at one layer only; classify errors; honor `Retry-After`. Sharpens `engineering-standards` R3. Applies: `(?i)(retr(y|ies)|backoff|attempt)`. Source: https://sre.google/sre-book/addressing-cascading-failures/ (retries at three layers turn one action into 4^3 = 64 attempts)
- `SRV-18` A handler that starts an expensive stage (DB write, LLM call, fan-out) without checking the request's cancellation signal or remaining deadline, or passes a fresh fixed timeout downstream instead of the remainder → check the signal before each stage and pass the absolute deadline. Sharpens `engineering-standards` R1. Applies: `(?i)(fetch\(|timeout|deadline|AbortSignal|signal|context\.With|ctx\.Done)`. Source: https://sre.google/sre-book/addressing-cascading-failures/ (the server should check the deadline left at each stage before doing more work; propagate one absolute deadline)
- `SRV-20` Concurrency that grows with input (`Promise.all(items.map(...))`, a goroutine or task per item, `asyncio.gather(*...)`) over a client- or data-sized list → a fixed concurrency limit and a cap on list size. Applies: `(?i)(Promise\.(all|allSettled|any)|asyncio\.gather|go\s+func|errgroup|ThreadPool|parallel)`. Source: https://sre.google/sre-book/addressing-cascading-failures/ (bound queues and in-flight work; reject early); https://api-security.owasp.org/editions/2023/en/0xa4-unrestricted-resource-consumption/
- `SRV-21` A new endpoint that triggers a costly or abusable action per call (LLM call, email/SMS/push send, account creation, file processing) with no per-principal rate limit or quota → a per-user or per-key limit returning 429. Applies: `(?i)(\.(post|put)\s*\(|@(Post|Put)|sendEmail|send_?sms|push|messages\.create|responses\.create|generate|completion)`. Source: https://api-security.owasp.org/editions/2023/en/0xa6-unrestricted-access-to-sensitive-business-flows/; https://api-security.owasp.org/editions/2023/en/0xa4-unrestricted-resource-consumption/
- `SRV-22` A server-side fetch of a URL, host, or redirect target that comes from the request, a stored user value, or an LLM → an allowlist of schemes and hosts, no private/link-local addresses, redirects not followed blindly. Applies: `(?i)(fetch\(|axios|got\(|requests\.(get|post)|urlopen|http\.(Get|Post|NewRequest)|redirect)`. Source: https://api-security.owasp.org/editions/2023/en/0xa7-server-side-request-forgery/
- `SRV-23` A per-user response with `Cache-Control: public`, `s-maxage`, or a shared-cache put (CDN, `caches.default`) keyed without the user, or a cookie-authenticated response with no `Cache-Control: private`/`no-store` → mark it private or key the cache by user. Applies: `(?i)(cache-control|s-maxage|\bpublic\b|max-age|caches\.default|cache\.put|cf:\s*\{)`. Source: https://www.rfc-editor.org/rfc/rfc9111#section-5.2.2.7 (private: a shared cache must not store the response); https://www.rfc-editor.org/rfc/rfc9111#section-3.5
