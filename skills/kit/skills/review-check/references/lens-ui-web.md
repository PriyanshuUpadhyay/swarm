# Web UI lens

These rules check UI states, forms, motion, layout, and accessibility in web UI code. The React
lens (`RE-`) owns the rules for clickable divs, image `alt`, icon-only names, input labels,
`outline: none`, and image dimensions in `.tsx`/`.jsx`; here those checks cover only `.vue`,
`.svelte`, and `.html`.

Files: `**/*.{tsx,jsx,vue,svelte,html,css,scss}`

- `UW-1` A data view (list, table, feed, detail page, search result) that renders only the success path, with no loading, empty, or error branch → render all three: a placeholder while loading, an empty state that says what to do next, and an error state with a retry. Files: `**/*.{tsx,jsx,vue,svelte,html}`. Source: Impeccable harden guide (a view that works only with perfect data breaks on no data, slow network, and API errors)
- `UW-2` A submit or action control that stays clickable while its request runs, or a handler with no in-flight guard, so a second click sends the request again → disable or guard the control from request start until it settles, and show a pending label or spinner ("Saving…"); keep it enabled before the request starts. Files: `**/*.{tsx,jsx,vue,svelte,html}`. Applies: `onClick|onSubmit|<form|<button|<Button|@click|@submit|on:click|on:submit|v-on:|action=|formAction|useActionState|useFormStatus|mutate`. Source: Web Interface Guidelines (Forms: submit button stays enabled until the request starts, spinner during the request)
- `UW-3` A destructive action (delete, remove, discard, revoke, leave, reset) that runs at once on one click → a confirmation dialog that names what is lost, or an undo window before the change is final. Files: `**/*.{tsx,jsx,vue,svelte,html}`. Source: Web Interface Guidelines (Navigation & State: destructive actions need a confirmation modal or undo window, never immediate)
- `UW-4` An optimistic update that changes the UI before the server confirms, with no rollback when the request fails → keep the previous value, restore it on failure, and show the error. Files: `**/*.{tsx,jsx,vue,svelte,html}`. Source: Impeccable harden guide (Concurrent operations: optimistic updates with rollback; otherwise the UI shows a change the server never saved)
- `UW-5` A validation error shown only in a toast, alert, or page-top banner, or not tied to its field → show the message next to the field, link it with `aria-describedby`, set `aria-invalid`, and move focus to the first invalid field on submit. Files: `**/*.{tsx,jsx,vue,svelte,html}`. Source: Web Interface Guidelines (Forms: errors inline next to fields; focus first error on submit) ; https://www.w3.org/WAI/WCAG22/Understanding/error-identification.html
- `UW-6` A failed submit that clears the form, resets fields, or removes the error messages before the user fixes them → keep the entered values and the field errors until the user edits that field or submits again. Files: `**/*.{tsx,jsx,vue,svelte,html}`. Source: Impeccable harden guide (Form validation errors: preserve user input on error)
- `UW-7` Filters, tabs, sort, pagination, search text, or an open panel or selected item held only in component state → put it in the URL query or path so reload, back, and a shared link restore the view. Files: `**/*.{tsx,jsx,vue,svelte,html}`. Source: Web Interface Guidelines (Navigation & State: URL reflects state; deep-link all stateful UI)
- `UW-8` Navigation done in a click handler (`router.push`, `navigate(...)`, `location.href =`, `goto(...)`) on a button or other non-link → an `<a href>` or the router's `<Link>`. Files: `**/*.{tsx,jsx,vue,svelte,html}`. Applies: `router\.(push|replace)|navigate\(|location\.(href|assign|replace)|window\.open\(|goto\(|\$router`. Source: Web Interface Guidelines (links use `<a>`/`<Link>` so Cmd/Ctrl-click, middle-click, and open-in-new-tab work)
- `UW-9` A new animation, transition, auto-scroll, or parallax with no `prefers-reduced-motion` variant → a reduced variant (cross-fade or no motion) under `@media (prefers-reduced-motion: reduce)` or the motion library's reduced-motion hook. Applies: `(?i)animation|transition|@keyframes|animate|motion|spring|scroll-behavior|scrollIntoView|scrollTo|parallax|autoplay`. Source: Web Interface Guidelines (Animation: honor `prefers-reduced-motion`) ; https://www.w3.org/WAI/WCAG22/Understanding/animation-from-interactions.html
- `UW-10` `transition: all` (or `transition-all`), or an animation of `width`, `height`, `top`, `left`, or `margin` → list the properties, and animate `transform` and `opacity`. Applies: `(?i)transition|animat|@keyframes`. Scope: added. Source: Web Interface Guidelines (Animation: never `transition: all`; animate compositor-friendly properties only)
- `UW-11` Motion or media that plays by itself for more than 5 seconds next to other content (carousel, marquee, autoplay video, looping animation) with no pause, stop, or hide control → add the control, and stop decorative loops under reduced motion. Applies: `(?i)autoplay|setInterval|carousel|marquee|loop|infinite|animation`. Source: https://www.w3.org/WAI/WCAG22/Understanding/pause-stop-hide.html (moving content distracts and blocks reading for some users)
- `UW-12` A custom composite widget (menu, listbox, tabs, combobox, tree, slider, grid) without the keyboard model of its pattern (arrow keys, Home/End, Escape, roving `tabindex`), or any positive `tabindex` → follow the matching APG pattern, and use only `tabindex` `0` or `-1`. Files: `**/*.{tsx,jsx,vue,svelte,html}`. Source: https://www.w3.org/WAI/ARIA/apg/patterns/ (each widget role promises a specific keyboard behavior) ; https://www.w3.org/WAI/WCAG22/Understanding/keyboard.html
- `UW-13` A modal, drawer, or popover that does not move focus into itself, does not keep Tab inside while modal, does not close on Escape, or does not return focus to the trigger on close → native `<dialog>` with `showModal()` or the repo's dialog component. Files: `**/*.{tsx,jsx,vue,svelte,html}`. Applies: `(?i)dialog|modal|drawer|sheet|popover|overlay|lightbox`. Source: https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/ (focus management and Escape are required parts of a modal dialog)
- `UW-14` An interactive element with a new `:hover` or `hover:` style but no `:focus-visible` style of the same strength → add a visible `:focus-visible` style (use `:focus-within` for compound controls). Applies: `(?i):hover|hover:|onMouseEnter|@mouseenter|on:mouseenter`. Source: Web Interface Guidelines (Focus States: interactive elements need visible focus; use `:focus-visible` over `:focus`)
- `UW-15` `outline: none`, `outline: 0`, or an `outline-none` class with no replacement focus style in a Vue, Svelte, or HTML file → a visible `:focus-visible` style. Files: `**/*.{vue,svelte,html}`. Applies: `outline\s*:\s*(none|0)|outline-none`. Source: https://www.w3.org/WAI/WCAG22/Understanding/focus-visible.html (keyboard users must see which element has focus)
- `UW-16` A new sticky or fixed header, footer, or banner that can cover the focused element or a scrolled-to anchor → `scroll-padding-top`/`scroll-margin-top` equal to its height, or a layout that keeps focus visible. Applies: `(?i)sticky|fixed|position|z-index|\bz-\d`. Source: https://www.w3.org/WAI/WCAG22/Understanding/focus-not-obscured-minimum.html (a covered focused element cannot be seen) ; Web Interface Guidelines (Focus States: sticky overlays must not cover the focused element)
- `UW-17` A click handler on a non-interactive element (`<div @click>`, `<span on:click>`, `<li onclick>`) in a Vue, Svelte, or HTML file → a `<button>` or `<a href>`; if a native element is impossible, add `role`, `tabindex="0"`, and Enter/Space handling. Files: `**/*.{vue,svelte,html}`. Applies: `(?i)@click|on:click|onclick|v-on:click|@mousedown|on:mousedown`. Source: https://www.w3.org/WAI/WCAG22/Understanding/keyboard.html (a div is not focusable, so keyboard users cannot reach it)
- `UW-18` An `<img>` with no `alt`, or an icon-only `<button>`/`<a>` with no accessible name, in a Vue, Svelte, or HTML file → `alt` text (`alt=""` for decoration), or `aria-label`/visually hidden text. Files: `**/*.{vue,svelte,html}`. Applies: `(?i)<(img|svg|button|a)\b|\balt=|aria-label`. Source: https://www.w3.org/WAI/WCAG22/Understanding/non-text-content (non-text content needs a text alternative)
- `UW-19` An `<input>`, `<select>`, or `<textarea>` with no associated label (placeholder only) in a Vue, Svelte, or HTML file → `<label for>`, a wrapping `<label>`, or `aria-labelledby`. Files: `**/*.{vue,svelte,html}`. Applies: `(?i)<(input|select|textarea)\b|placeholder=`. Source: https://www.w3.org/WAI/WCAG22/Understanding/labels-or-instructions.html (placeholders disappear on input, so the field loses its name)
- `UW-20` A decorative icon or SVG next to visible text with no `aria-hidden="true"` → hide it from assistive tech so the name is read once. Files: `**/*.{tsx,jsx,vue,svelte,html}`. Applies: `(?i)<svg|Icon\b|<i\b|lucide|heroicon`. Source: Web Interface Guidelines (Accessibility: decorative icons need `aria-hidden="true"`)
- `UW-21` A status that appears without a page change (toast, "Saved", inline validation, result count, loading done) and is not in a live region → `aria-live="polite"` or `role="status"` (`role="alert"` for errors). Files: `**/*.{tsx,jsx,vue,svelte,html}`. Source: Web Interface Guidelines (Accessibility: async updates need `aria-live="polite"`) ; https://www.w3.org/WAI/WCAG22/Understanding/status-messages.html
- `UW-22` A text input with the wrong or missing `type`/`inputmode` (email, tel, url, number), no `autocomplete` on personal or auth fields, or no meaningful `name` → set them; turn off `spellcheck` on emails, codes, and usernames. Files: `**/*.{tsx,jsx,vue,svelte,html}`. Applies: `(?i)<(input|textarea)\b|type=|autocomplete|inputmode`. Source: Web Interface Guidelines (Forms: `autocomplete`, meaningful `name`, correct `type` and `inputmode`) ; https://www.w3.org/WAI/WCAG22/Understanding/identify-input-purpose.html
- `UW-23` Paste blocked on an input (`onPaste`/`@paste` with `preventDefault`) → allow paste. Applies: `(?i)paste`. Source: Web Interface Guidelines (Forms: never block paste; password managers and one-time codes need it)
- `UW-24` A viewport meta with `user-scalable=no` or `maximum-scale=1`, or text sized in `px` on a root that blocks browser text scaling → remove the zoom limit; size text in `rem`. Applies: `(?i)user-scalable|maximum-scale|font-size|viewport`. Scope: added. Source: Web Interface Guidelines (Anti-patterns: disabling zoom) ; https://www.w3.org/WAI/WCAG22/Understanding/resize-text.html
- `UW-25` A pointer target smaller than 24 by 24 CSS px without spacing to its neighbors (icon button, close X, inline link-button, row action), or a checkbox or radio whose label is not part of the hit area → at least 24 by 24 px (44 px for touch-first controls), and one shared hit area for label and control. Files: `**/*.{tsx,jsx,vue,svelte,html,css,scss}`. Source: https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html (small targets cause missed and wrong taps) ; Web Interface Guidelines (Forms: checkbox and label share one hit target, no dead zones)
- `UW-26` Content that pushes the layout when it arrives: a spinner replaced by taller content, a banner or result inserted above what the user reads, an embed or font with no reserved space, or an `<img>`/`<iframe>` with no `width`/`height` in a Vue, Svelte, or HTML file → reserve the final size (skeleton of the same size, `min-height`, `aspect-ratio`, dimensions) and add new content below the reading position. Source: https://web.dev/articles/optimize-cls (unexpected shifts make users lose their place and click the wrong target)
- `UW-27` A text container that cannot hold long or translated text: fixed width on a button or label, `white-space: nowrap` with no truncation, a flex child with no `min-width: 0`, user content with no `overflow-wrap` → let it wrap or truncate on purpose (`truncate`, `line-clamp`, `break-words`), and size buttons by padding, not width. Source: Web Interface Guidelines (Content Handling: text containers handle long content; flex children need `min-w-0`) ; Impeccable harden guide (translations run 30 to 40 percent longer)
- `UW-28` New `left`/`right` margin, padding, border, position, or text alignment in an app that ships a right-to-left locale → logical properties (`margin-inline-start`, `inset-inline-end`, `text-align: start`, Tailwind `ms-`/`me-`/`ps-`/`pe-`). Applies: `(?i)(margin|padding|border)-(left|right)|\b(left|right)\s*:|\b-?(ml|mr|pl|pr|left|right)-|text-align\s*:\s*(left|right)|text-(left|right)\b|float`. Source: Impeccable harden guide (RTL support: use logical properties)
- `UW-29` A date, time, number, or currency built with a fixed format (`toFixed`, manual `/` or `,` joins, month-name arrays), or a plural built by adding "s" → `Intl.DateTimeFormat`, `Intl.NumberFormat`, `Intl.PluralRules`, or the repo's i18n library. Files: `**/*.{tsx,jsx,vue,svelte,html}`. Source: Web Interface Guidelines (Locale & i18n: use `Intl.*`, not hardcoded formats) ; Impeccable harden guide (Pluralization)
- `UW-30` A fixed or full-bleed bar, bottom sheet, or edge-to-edge layout on mobile that ignores the device safe areas → `env(safe-area-inset-*)` padding with `viewport-fit=cover`. Applies: `(?i)fixed|sticky|position|inset|bottom|viewport-fit|safe-area|100[dsl]?vh`. Source: Web Interface Guidelines (Safe Areas & Layout: full-bleed layouts need `env(safe-area-inset-*)`)
- `UW-31` A new raw color (`#fff`, `rgb(...)`, `bg-white`, `text-black`, a gray scale step) in a themed app instead of the theme token or CSS variable, or a dark theme with no `color-scheme` → the semantic token, and `color-scheme: light dark` on the root. Applies: `(?i)#[0-9a-f]{3,8}\b|rgba?\(|hsla?\(|oklch\(|\b(bg|text|border|fill|stroke|ring)-(white|black|gray|slate|zinc|neutral|stone)|color-scheme|prefers-color-scheme|\bcolor\s*:|background`. Source: Web Interface Guidelines (Dark Mode & Theming: `color-scheme: dark`; native controls need explicit colors) (a raw color does not switch with the theme, so text or surfaces vanish in the other mode)
- `UW-32` A custom look-alike of a native control (select, checkbox, radio, switch, date input, range, dialog) built from `div`s → the native element or the repo's accessible component; custom only with the full ARIA pattern. Files: `**/*.{tsx,jsx,vue,svelte,html}`. Source: Web Interface Guidelines (Accessibility: semantic HTML before ARIA) ; https://www.w3.org/WAI/ARIA/apg/practices/read-me-first/ (no ARIA is better than bad ARIA)
- `UW-33` A form or editor with unsaved changes that lets route change, tab close, or modal close drop them silently → a `beforeunload` or router guard, or autosave. Files: `**/*.{tsx,jsx,vue,svelte,html}`. Source: Web Interface Guidelines (Forms: warn before navigation with unsaved changes)
- `UW-34` A user-facing error that states only the failure ("Error", "Something went wrong", a raw `error.message` or status code) → say what happened and the next step (retry, fix field X, sign in again). Files: `**/*.{tsx,jsx,vue,svelte,html}`. Applies: `(?i)error|fail|wrong|invalid|catch|reject`. Source: Web Interface Guidelines (Content & Copy: error messages include the fix or next step)
- `UW-35` An action that needs a drag, swipe, pinch, or long press with no single-click or keyboard alternative → add a button or menu item that does the same thing. Applies: `(?i)drag|swipe|pinch|pointer(down|move)|touch(start|move)|long-?press|gesture|sortable|dnd`. Source: Web Interface Guidelines (Touch & Interaction: gestures need tap/click and keyboard alternatives) ; https://www.w3.org/WAI/WCAG22/Understanding/dragging-movements.html
- `UW-36` A new `:hover` style that changes color, size, or layout outside `@media (hover: hover) and (pointer: fine)`, or a Tailwind v3 `hover:` class without `future.hoverOnlyWhenSupported` → put the hover rules inside that media query, and give touch its press feedback through `:active` (Tailwind v4 `hover:` already compiles to the hover query). Applies: `(?i):hover|hover:`. Scope: added. Source: emilkowalski/skills `mobile-native` at `e8a175d` (Hover state stuck after tap: a tap applies `:hover` and leaves it there until the next tap elsewhere)
- `UW-37` `100vh`, `h-screen`, or `min-h-screen` on an app shell, drawer, sheet, or bottom-pinned control → `100dvh` (`h-dvh`) for UI that tracks the visible area, `100svh` (`min-h-svh`) for a hero or first screen. Applies: `(?i)100vh|\bh-screen\b|min-h-screen|max-h-screen`. Scope: added. Source: emilkowalski/skills `mobile-native` at `e8a175d` (Layout has the wrong height: mobile `100vh` is the height with the URL bar hidden, so the element overflows on load and a bottom-pinned button sits under the bar)
- `UW-38` An `<input>`, `<textarea>`, or `<select>` whose font size is below 16px on touch devices (`text-xs`, `text-sm`, `font-size` under `1rem`) → 16px at least, or 16px under `@media (pointer: coarse)`; never fix the zoom with a viewport limit (`UW-24`). Applies: `(?i)<(input|textarea|select)\b|font-size|\btext-(xs|sm)\b`. Source: emilkowalski/skills `mobile-native` at `e8a175d` (Page zooms into the input: iOS Safari zooms on focus below 16px and does not zoom back out)
- `UW-39` `user-select: none` (or `select-none`) on `body`, the root, or a content container → only on controls (buttons, tabs, chips, drag handles), with `-webkit-user-select` for Safari. Applies: `(?i)user-select|select-none`. Scope: added. Source: emilkowalski/skills `mobile-native` at `e8a175d` (Long-press selects button text: control labels should not select, but users copy addresses, errors, and order numbers from content)
