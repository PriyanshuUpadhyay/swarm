# Swift lens

These rules add checks for Swift language, memory, and concurrency.

Files: `**/*.swift`

- `SW-1` A force unwrap (`x!`, `f()!`, `.first!`) or an implicitly unwrapped declaration (`var x: T!`) on a value that can be nil at run time (external input, decoding, lookup, `URL(string:)` built from data, weak reference) → `guard let` / `if let` / `??` with a handled nil path. Say why nil is impossible when the unwrap stays. Applies: `[\w\)\]]!([^=]|$)`. Source: https://docs.swift.org/swift-book/documentation/the-swift-programming-language/thebasics/ (using `!` on a nil optional triggers a runtime error, so the app crashes)
- `SW-2` `try!` on a call that can throw with real data (file, network, decode, regex built from input, database) → `do`/`catch` or `try` with propagation. Applies: `try!`. Source: https://docs.swift.org/swift-book/documentation/the-swift-programming-language/errorhandling/ ("If an error actually is thrown, you'll get a runtime error.")
- `SW-3` A forced downcast `as!` where the dynamic type comes from data, a framework callback, `Any`, or a dequeued view/cell → `as?` with a handled failure, or `guard let ... as? ... else { assertionFailure; return }`. Applies: `as!`. Source: https://docs.swift.org/swift-book/documentation/the-swift-programming-language/typecasting/ (the forced form triggers a runtime error when the downcast is to the wrong type)
- `SW-4` An escaping closure that a class instance stores or keeps alive (stored property, Combine `sink`, Timer/NotificationCenter block, `DispatchWorkItem`, long-lived `Task`, completion held by a long-lived object) that captures `self` strongly → `[weak self]` and a `guard let self` exit, or proof the closure is released (runs once and is dropped). Applies: `\bself\b`. Source: https://docs.swift.org/swift-book/documentation/the-swift-programming-language/automaticreferencecounting/ ("A strong reference cycle can also occur if you assign a closure to a property of a class instance, and the body of that closure captures the instance.")
- `SW-5` `unowned` (capture list or property) where the referenced object can be deallocated before the holder, for example a capture in a closure that outlives the owner or runs async → `weak`. Keep `unowned` only when both "always refer to each other and are deallocated at the same time". Applies: `\bunowned\b`. Source: https://docs.swift.org/swift-book/documentation/the-swift-programming-language/automaticreferencecounting/ (access to a deallocated unowned reference is a runtime error)
- `SW-6` A `delegate`, `dataSource`, or parent back-reference stored as a strong `var`/`let` in a class → `weak var` with a class-bound (`AnyObject`) protocol. Applies: `(?i)\b(var|let)\s+\w*(delegate|datasource|parent|owner)\b`. Source: https://realm.github.io/SwiftLint/weak_delegate.html ("Delegates should be weak to avoid reference cycles"); https://docs.swift.org/swift-book/documentation/the-swift-programming-language/automaticreferencecounting/ (strong cycles between class instances)
- `SW-7` An unstructured `Task { }` / `Task.detached { }` whose handle is discarded while the work is long, loops (`for await`, `while`), or must stop when its owner goes away (view controller, model, session) → store the `Task` and call `cancel()` in the owner's teardown, or use structured concurrency (`async let`, task group, SwiftUI `.task`). Applies: `\bTask(\.detached)?\s*(\(|\{)`. Source: https://developer.apple.com/documentation/swift/task/init(name:priority:operation:) ("Discarding your reference to a task doesn't implicitly cancel that task"); https://docs.swift.org/swift-book/documentation/the-swift-programming-language/concurrency/ (for unstructured tasks "you're also completely responsible for their correctness")
- `SW-8` A `Task { }` whose body calls `try` with no `do`/`catch` inside and whose `value` nobody awaits → catch and surface the error inside the task. Applies: `\bTask(\.detached)?\s*(\(|\{)`. Source: https://developer.apple.com/documentation/swift/task/init(name:priority:operation:) (the error is rethrown only when `value` is awaited, "Take care to not accidentally dismiss errors"); https://realm.github.io/SwiftLint/unhandled_throwing_task.html
- `SW-10` A `withCheckedContinuation` / `withUnsafeContinuation` (throwing or not) where some path resumes zero times or more than once (early return, error branch, delegate method called repeatedly, callback that can fire twice) → exactly one `resume` on every path. Prefer the checked variant in new code. Applies: `with(Checked|Unsafe)(Throwing)?Continuation|\.resume\(`. Source: https://developer.apple.com/documentation/swift/checkedcontinuation ("You must call a resume method exactly once on every execution path"; resuming twice is undefined behavior, never resuming leaks the task)
- `SW-11` A new `@unchecked Sendable` conformance or `nonisolated(unsafe)` declaration where some mutable member is not guarded by the same lock/queue on every access → name the guard for each member, or use an `actor`, `Mutex`, or immutable `let` state. Applies: `@unchecked\s+Sendable|nonisolated\(unsafe\)`. Source: https://www.swift.org/migration/documentation/swift-6-concurrency-migration-guide/commonproblems ("Only use nonisolated(unsafe) when you are carefully guarding all access to the variable with an external synchronization mechanism"); https://github.com/swiftlang/swift-evolution/blob/main/proposals/0302-concurrent-value-and-concurrent-closures.md (`@unchecked` "requires the author of the type to ensure that this is safe")
- `SW-12` A new global or `static var` (mutable shared state) → `let` of a `Sendable` type, isolation to a global actor (`@MainActor`), or an actor that owns it. Applies: `(?m)(^|\s)static\s+var\b|^\s*((public|private|fileprivate|internal)\s+)?var\s`. Source: https://github.com/swiftlang/swift-evolution/blob/main/proposals/0412-strict-concurrency-for-global-variables.md (a global must be isolated to a global actor, or be immutable and `Sendable`)
- `SW-13` A blocking wait (`DispatchSemaphore.wait`, `DispatchGroup.wait`, `Thread.sleep`, `sleep`, sync file/network I/O) inside an `async` function or used to turn async work back into sync → `await` the work, or `Task.sleep`. Applies: `DispatchSemaphore|\.wait\(|Thread\.sleep|\busleep\(|\bsleep\(`. Source: https://developer.apple.com/videos/play/wwdc2021/10254/ ("primitives like semaphores and condition variables are unsafe to use with Swift concurrency" because they hide dependencies from the runtime and can starve the cooperative pool)
- `SW-14` `DispatchQueue.main.sync` or `queue.sync` that can run on that same queue (called from main, from a `@MainActor` context, or re-entrantly from the queue's own work) → `async`, or an actor/`await`. Applies: `\.sync\s*(\(|\{)`. Source: https://developer.apple.com/documentation/dispatch/dispatchqueue/sync(execute:) ("Calling this function and targeting the current queue results in deadlock.")
- `SW-15` A closure passed to an Objective-C or not-yet-migrated API (completion handler, delegate queue, audio tap, KVO, `@preconcurrency import`) from inside a `@MainActor` type, where the API may call it on another thread → mark the closure `@Sendable` and hop with `Task { @MainActor in }`, or mark the method `nonisolated`. Applies: `@preconcurrency|[Hh]andler|[Cc]allback|installTap|queue:|@objc`. Source: https://www.swift.org/migration/documentation/swift-6-concurrency-migration-guide/incrementaladoption (the closure inherits `MainActor` isolation by mistake, and "This code will compile without issue but crash at runtime.")
- `SW-16` `MainActor.assumeIsolated` (or `preconditionIsolated`) in code that a caller can reach from a background thread or queue → prove every caller is on main, or use `await MainActor.run` / `Task { @MainActor in }`. Applies: `assume(Isolated)|preconditionIsolated`. Source: https://developer.apple.com/documentation/swift/mainactor/assumeisolated(_:file:line:) ("If the current context is not running on the actor's serial executor ... this method will crash with a fatal error")
- `SW-17` A `Task.detached` added to move work off the main actor that captures `self` or actor-isolated state, or relies on task-local values or priority → a `nonisolated`/`@concurrent` async function called from a normal `Task`, or pass only `Sendable` copies in. Applies: `Task\.detached`. Source: https://github.com/swiftlang/swift-evolution/blob/main/proposals/0304-structured-concurrency.md (a detached task "does not inherit priority, task-local values, or the actor context")
- `SW-18` A long loop or multi-step async operation (pagination, retries, batch processing, `for await` over a stream) with no cancellation check → `try Task.checkCancellation()` or `Task.isCancelled` per iteration, or `withTaskCancellationHandler` around a callback API. Applies: `\b(while|for|repeat)\b`. Source: https://github.com/swiftlang/swift-evolution/blob/main/proposals/0304-structured-concurrency.md ("cancellation has no effect at all unless something checks for cancellation")
- `SW-19` In a Swift 5 language-mode target, a mutable `var` or non-`Sendable` class instance captured and mutated by work that runs concurrently (`TaskGroup.addTask`, `DispatchQueue.global().async`, `concurrentPerform`, `async let`) → pass copies, collect results through the group, or isolate the state. Applies: `addTask|concurrentPerform|DispatchQueue\.global|async\s+let|\.async\s*(\(|\{)`. Source: https://github.com/swiftlang/swift-evolution/blob/main/proposals/0302-concurrent-value-and-concurrent-closures.md (`@Sendable` closures "can only use by-value captures"; Swift 5 mode does not enforce it everywhere)
- `SW-21` Work in `deinit` that extends the life of `self` (creates a `Task` or escaping closure that captures `self`, calls async/isolated methods through `self`) → do the cleanup synchronously with non-`self` values, or move it to an explicit `close()`/`stop()`. Applies: `\bdeinit\b`. Source: https://www.swift.org/migration/documentation/swift-6-concurrency-migration-guide/commonproblems ("**Never** extend the life-time of `self` from within `deinit`. Doing so will crash at runtime.")
- `SW-23` A hand-written `==` or `hash(into:)` where the two use different fields (or one was changed and the other was not) → feed exactly the fields that `==` compares to the `Hasher`, or use the synthesized conformance. Applies: `static\s+func\s+==|func\s+hash\(into`. Source: https://developer.apple.com/documentation/swift/hashable ("Two instances that are equal must feed the same values to Hasher in hash(into:), in the same order.")
- `SW-24` A subscript or index arithmetic on a collection that can be empty or shorter than assumed (`items[0]`, `items[i + 1]`, `items[items.count - 1]`, a `String.Index` from another string) → `.first`/`.last`, `indices.contains(i)`, or a bounds `guard`. Applies: `\w\[[^\]]+\]`. Source: https://docs.swift.org/swift-book/documentation/the-swift-programming-language/collectiontypes/ (an index outside the array's bounds triggers a runtime error)
- `SW-25` A numeric conversion or arithmetic on untrusted or unbounded values that can trap (`Int(someDouble)` with NaN/infinity/out of range, narrowing `Int32(x)`, `a + b` or `a * b` on sizes, durations, or counters from input) → `Int(exactly:)`, `Int(clamping:)`, `.isFinite` check, or `addingReportingOverflow`. Applies: `\bU?Int(8|16|32|64)?\(|\b(UInt|Int)(8|16|32|64)\b`. Source: https://docs.swift.org/swift-book/documentation/the-swift-programming-language/advancedoperators/ (Swift arithmetic does not overflow by default; overflow is trapped and reported as an error)
- `SW-26` Overlapping access to one variable in a single statement (the same variable passed twice as `inout`, `&self.x` passed to a mutating method on `self`, a closure that writes a property while a mutating method on the same value runs) → copy to a local first, then write back. Applies: `&\w|\binout\b|\bmutating\b`. Source: https://docs.swift.org/swift-book/documentation/the-swift-programming-language/memorysafety/ (conflicting access to memory gives a compile-time or runtime error)
- `SW-27` `fatalError`, `preconditionFailure`, or `precondition` on a path that data from outside the process can reach (server response, file content, user input, a new enum case from a framework) → throw or return a handled error. Keep a trap only for a programmer error that no input can cause. Applies: `fatalError\(|precondition(Failure)?\(`. Source: https://docs.swift.org/swift-book/documentation/the-swift-programming-language/thebasics/ (preconditions stop the program in production builds when they fail)
- `SW-28` A new public or module-level API whose name hides its side effects or cost: a mutating method named as a noun or `-ed` form, a non-mutating one named as an imperative verb, a Boolean that does not read as an assertion (`isEmpty`, `hasX`), or a computed property that is not O(1) with no complexity note → rename to the guideline form, or document the complexity. Applies: `\b(public|open|package)\b.*\b(func|var)\b|\bvar\s+\w+\s*:\s*Bool\b`. Source: https://www.swift.org/documentation/api-design-guidelines/ (side-effect names are imperative verbs; nonmutating pairs use -ed/-ing; "Document the complexity of any computed property that is not O(1).")
