# TypeScript and JavaScript lens

These rules add checks for TypeScript and JavaScript code in any runtime.

Files: `**/*.{ts,tsx,mts,cts,js,jsx,mjs,cjs}`

- `TS-1` A promise-returning call used as a bare statement (no `await`, `return`, `.catch(handler)`, or `.then(_, handler)`), including in a constructor or a sync function → await or return it, or attach a rejection handler. `void` is TS-33. Check: `oxlint:typescript/no-floating-promises`. Source: https://typescript-eslint.io/rules/no-floating-promises/ (floating promises cause mis-sequenced operations and ignored rejections; in Node an unhandled rejection ends the process by default, https://nodejs.org/api/process.html (event `unhandledRejection`))
- `TS-2` An async function passed where a void callback is expected (`forEach`, `addEventListener`, `.on(...)`, `setTimeout`, JSX `onX`), an async predicate in `filter`/`some`/`every`/`find`, or a promise used as a condition (`if (p)`, `p && ...`) → `for...of` with `await` or `await Promise.all(xs.map(...))`; await the predicate results first; await the promise before the test. Applies: `async\b|forEach\(|\.(filter|some|every|find|findIndex)\(|addEventListener|\.on\(|setTimeout|setInterval|\bon[A-Z]\w*=|\bif\s*\(|&&|\?`. Source: https://typescript-eslint.io/rules/no-misused-promises/ (a void-return slot drops the promise, so rejections are unhandled and order is lost; a promise is always truthy)
- `TS-4` `any` enters typed code: an explicit `any`, `as any`, or an untyped `JSON.parse(...)`, `await res.json()`, or `catch (e)` value assigned, returned, passed, or member-accessed without narrowing → `unknown` plus a type guard or a schema parse at the trust boundary (lens owns where the boundary is). Applies: `\bany\b|JSON\.parse\(|\.json\(\)`. Source: https://typescript-eslint.io/rules/no-explicit-any/ (`any` turns off type checking for that value) ; https://typescript-eslint.io/rules/no-unsafe-assignment/ (an `any` value assigned to a typed slot spreads unchecked data)
- `TS-5` A type assertion (`x as T`, `<T>x`, `as unknown as T`) on a value whose type the code has not proven, most often on parsed input or a narrowed union → a type annotation, a type guard, or a runtime check that throws. Applies: `\bas\s+[\w{\[(]|<[A-Z]\w*>\s*[\w(]`. Source: https://google.github.io/styleguide/tsguide.html#type-and-non-nullability-assertions (assertions are unsafe, the compiler does not insert runtime checks, so a wrong assertion fails far from the cause) ; https://typescript-eslint.io/rules/consistent-type-assertions/
- `TS-6` A non-null assertion (`x!`, `x!.y`, `map.get(k)!`) → an explicit check that throws a named error or handles the missing case. Applies: `[\w)\]]!([^=]|$)`. Scope: added. Source: https://typescript-eslint.io/rules/no-non-null-assertion/ (it tells the compiler a value cannot be null with no proof, so a later change makes it crash at runtime)
- `TS-7` An index read (`arr[i]`, `arr[0]`, `record[key]`, `.at(-1)`, destructuring `const [first] = arr`) used as defined when the repo does not set `noUncheckedIndexedAccess` → a length or `undefined` check before use. Applies: `\w[\])]?\[[^\]]+\]|\.at\(|const\s*\[`. Source: https://www.typescriptlang.org/tsconfig/noUncheckedIndexedAccess.html (without the flag TS types an indexed read as `T`, not `T | undefined`)
- `TS-8` A `switch` or `if` chain over a union or enum with no exhaustiveness check, or a hunk that adds a member to a union/enum while a `switch` elsewhere has a `default` that silently absorbs it → `default: { const _x: never = v; throw ... }` (or the repo's `assertNever`), and name each switch that must handle the new member. Applies: `(?m)\bswitch\s*\(|\bcase\b|\benum\b|^\+?.*\|\s*['"\w]|\btype\s+\w+\s*=`. Source: https://typescript-eslint.io/rules/switch-exhaustiveness-check/ (a missed union member falls through at runtime with no compile error)
- `TS-9` A falsy test where `0`, `""`, `NaN`, or `false` are valid values: `x || fallback`, `if (!count)`, `if (str)`, `nullableBool && ...` → `??`, `== null`, or an explicit comparison. Applies: `\|\||&&|!\w|\bif\s*\(|\?`. Source: https://typescript-eslint.io/rules/prefer-nullish-coalescing/ (`||` also replaces falsy values like 0 and "") ; https://typescript-eslint.io/rules/strict-boolean-expressions/ (implicit boolean coercion of numbers and strings hides the 0 / "" case)
- `TS-10` A `catch (e)` or `.catch((e) => ...)` that reads `e.message`, `e.code`, or `e.stack` without narrowing, or annotates `e: any` → `e: unknown` plus `e instanceof Error` (or a code check) before the read. Applies: `catch\s*\(|\.catch\(`. Source: https://www.typescriptlang.org/tsconfig/useUnknownInCatchVariables.html (anything can be thrown, so the catch variable is `unknown`) ; https://typescript-eslint.io/rules/use-unknown-in-catch-callback-variable/
- `TS-11` A `throw` of a string, object literal, or other non-`Error`, or `reject(...)`/`Promise.reject(...)` with a non-`Error` → throw or reject an `Error` (or subclass). Applies: `\bthrow\b|reject\(`. Source: https://typescript-eslint.io/rules/only-throw-error/ (only `Error` objects carry a stack trace; callers that check `instanceof Error` miss the rest) ; https://typescript-eslint.io/rules/prefer-promise-reject-errors/
- `TS-12` A `catch` that throws a new error without the caught one → `new Error(msg, { cause: err })`. Applies: `\bthrow\s+new\b`. Source: https://eslint.org/docs/latest/rules/preserve-caught-error (re-thrown errors that omit `cause` lose the original debugging information)
- `TS-13` `return somePromise` (no `await`) inside a `try` whose `catch` or `finally` must see that rejection, or inside a `using`/lock scope → `return await`. Applies: `\btry\b|\breturn\s+\S`. Source: https://typescript-eslint.io/rules/return-await/ (without `await` the rejection escapes the surrounding try/catch and `finally` runs before the promise settles)
- `TS-14` `fetch(...)` whose response body is used without a `res.ok` or `res.status` check → check and throw (or return a typed failure) before `.json()`/`.text()`. Applies: `\bfetch\(|\.json\(\)|\.text\(\)|\.arrayBuffer\(\)`. Source: https://developer.mozilla.org/en-US/docs/Web/API/Fetch_API/Using_Fetch#checking_response_status (fetch fulfills on 404/500; only network errors reject)
- `TS-16` `.sort()` with no comparator on numbers or objects, or `.sort()`/`.reverse()`/`.splice()`/`.fill()` on an array the function did not create (a parameter, a cached or module value, props, state) → a comparator (`(a, b) => a - b`, `localeCompare`), and `toSorted`/`toReversed`/`toSpliced` or a copy. Applies: `\.(sort|reverse|splice|fill|copyWithin)\(`. Source: https://typescript-eslint.io/rules/require-array-sort-compare/ (default sort compares as strings, so `[10, 2, 1]` sorts to `[1, 10, 2]`) ; https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Array/sort (sorts in place and returns the same array)
- `TS-17` A plain object used as a map keyed by external strings (`obj[userKey] = v`, `key in obj`, `obj.hasOwnProperty(k)`, deep merge of parsed JSON) → `Map`, `Object.create(null)`, or `Object.hasOwn`, and reject `__proto__`/`constructor`/`prototype` keys in merges. Applies: `\w\[[^\]'"\d][^\]]*\]\s*=|\bin\s+\w|hasOwnProperty|Object\.assign|merge|\.\.\.`. Source: https://developer.mozilla.org/en-US/docs/Web/Security/Attacks/Prototype_pollution (attacker keys like `__proto__` change every object's prototype) ; https://eslint.org/docs/latest/rules/no-prototype-builtins
- `TS-18` `// @ts-ignore`, `// @ts-nocheck`, `// @ts-expect-error` or `eslint-disable` with no reason, or one added to silence a new type error in changed code → fix the type; if a suppress must stay, `@ts-expect-error` with a one-line reason. Applies: `@ts-(ignore|expect-error|nocheck)|eslint-disable`. Source: https://typescript-eslint.io/rules/ban-ts-comment/ (`@ts-ignore` hides real errors and stays after they are fixed; `@ts-expect-error` fails once the error is gone)
- `TS-20` Parsing numbers from text with `parseInt` and no radix, or `Number(x)`/`parseFloat(x)`/`+x` with no `NaN` check, or `x === NaN` → `Number.parseInt(x, 10)` (or `Number(x)`) followed by `Number.isNaN`/`Number.isFinite`. Applies: `\bparse(Int|Float)\(|\bNumber\(|\bNaN\b|=\s*\+\w`. Source: https://eslint.org/docs/latest/rules/radix (no radix accepts `0x` input and older engines read leading-zero input as octal) ; https://eslint.org/docs/latest/rules/use-isnan (`NaN` is never equal to anything, itself included)
- `TS-21` An object, array, `undefined`, or nullable value interpolated into a template literal or `+` string (log lines, keys, SQL fragments, user text) → format the field you mean, or `JSON.stringify`, or a null branch. Applies: `\$\{|['"\x60]\s*\+|\+\s*['"\x60]|\.toString\(\)|\bString\(`. Source: https://typescript-eslint.io/rules/restrict-template-expressions/ (non-string values print as `[object Object]` or `undefined`) ; https://typescript-eslint.io/rules/no-base-to-string/
- `TS-22` `for...in` over an array, or over an object with no own-property guard → `for...of`, `Object.keys`/`Object.entries`, or `.forEach`. Applies: `\bfor\s*\(\s*(const|let|var)?\s*\w+\s+in\b`. Source: https://typescript-eslint.io/rules/no-for-in-array/ (it iterates string keys, including inherited and non-index ones, not values) ; https://eslint.org/docs/latest/rules/guard-for-in
- `TS-23` A `map`/`filter`/`find`/`some`/`every`/`reduce`/`flatMap`/`sort` callback with a block body that can end without `return` → return on every path, or `forEach`/`for...of` if no result is used. Applies: `\.(map|filter|find|findIndex|findLast|some|every|reduce|reduceRight|flatMap|sort|toSorted)\(`. Source: https://eslint.org/docs/latest/rules/array-callback-return (a missing return yields `undefined` elements or wrong filter results silently)
- `TS-24` `await` on a value that is not a promise, most often a function reference (`await save` for `await save()`), or `for await` over a sync iterable → call the function, or drop the `await`. Applies: `\bawait\b`. Check: `oxlint:typescript/await-thenable`. Source: https://typescript-eslint.io/rules/await-thenable/ (awaiting a non-thenable is a no-op and usually means a missing call or a wrong type)
- `TS-25` `new Promise(async (resolve, reject) => ...)`, or an executor that returns a value, or that does not call `reject` on its error path → move the async work outside and wrap only the callback API; call `reject` on every error path. Applies: `new Promise\s*[(<]`. Source: https://eslint.org/docs/latest/rules/no-async-promise-executor (an error thrown in an async executor is lost and the promise never settles) ; https://eslint.org/docs/latest/rules/no-promise-executor-return
- `TS-26` A `case` that falls into the next with no `break`/`return`/`throw` and no fallthrough comment → end the case, or add `// falls through`. Applies: `\bcase\b|\bdefault\s*:`. Check: `oxlint:eslint/no-fallthrough`. Source: https://eslint.org/docs/latest/rules/no-fallthrough (unintended fallthrough runs the next case's code)
- `TS-27` A listener, interval, timer, or subscription registered outside React (`addEventListener`, `emitter.on`, `setInterval`, `subscribe`) with no matching remove or dispose path, or registered per call on a long-lived object → return a disposer or remove it on the close path; register once. Applies: `addEventListener|\.on\(|\.once\(|setInterval|setTimeout|subscribe\(|new \w*Observer\(`. Source: https://nodejs.org/api/events.html (more than 10 listeners on one event warns of a possible memory leak) ; https://developer.mozilla.org/en-US/docs/Web/API/EventTarget/removeEventListener
- `TS-28` `==` or `!=` other than `== null` / `!= null` → `===` / `!==`. Applies: `[^=!<>]==[^=]|!=[^=]`. Scope: added. Source: https://eslint.org/docs/latest/rules/eqeqeq (loose equality coerces types, so `"" == 0` and `"0" == false` are true)
- `TS-29` An integer that can exceed 2^53 − 1 (64-bit ids, time-sortable 64-bit ids, nanosecond timestamps, DB `BIGINT`) held as `number` or read through `JSON.parse` → keep it a string or `bigint` end to end. Applies: `(?i)\bid\b|bigint|int64|nanos|\bNumber\(|parseInt|JSON\.parse`. Source: https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Number/MAX_SAFE_INTEGER (integers above it lose precision and compare equal to their neighbours)
- `TS-30` An optional chain, `??`, or null check on a value whose type is not nullable, or a condition that is always true or false by type → remove it, or fix the type that lies. Applies: `\?\.|\?\?|[!=]==?\s*(null|undefined)|\bif\s*\(`. Source: https://typescript-eslint.io/rules/no-unnecessary-condition/ (a dead branch means either dead code or a type that does not match runtime values)
- `TS-32` (web) A promise stored in a variable or field (`const p = save()`, `this.pending = load()`) that some path then returns from a non-async function, passes on as `unknown`, or drops, with no `await` and no rejection handler on that path → await it where it is used, or attach a handler where it is made. The `no-floating-promises` rule does not track stored promises, so lint stays green. Applies: `\b(const|let|var)\s+\w+\s*=\s*[\w.]+\(|this\.\w+\s*=\s*[\w.]+\(`. Source: https://github.com/typescript-eslint/typescript-eslint/issues/8170 (the rule ignores promises assigned to references); https://github.com/typescript-eslint/typescript-eslint/issues/4589. Confidence: medium.
- `TS-33` `void` before a promise-returning call with no comment that says why fire-and-forget is safe and where the error goes → add that comment, or await it or attach a rejection handler. Applies: `\bvoid\s+[\w.(]`. Scope: added. Source: https://typescript-eslint.io/rules/no-floating-promises/#ignorevoid (the rule allows `void` by default, so lint stays green and only a reader can check the reason)
