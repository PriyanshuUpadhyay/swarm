# CLI lens

These rules add checks for command-line entry points in any language; also apply them to any file that the diff shows is a command handler.

Files: `**/{cmd,cli,bin,scripts}/**, **/main.{go,py}, **/__main__.py, **/*.sh`

- `CLI-1` An error path that exits 0, a success path that exits non-zero, or an exit code changed for an existing failure mode → 0 on success, non-zero on failure, stable codes per failure class. Applies: `exit|Exit\(|return\s+\d|sys\.exit|raise SystemExit|process\.exit`. Source: https://clig.dev/#the-basics ("Return zero exit code on success, non-zero on failure. Exit codes are how scripts determine whether a program succeeded")
- `CLI-2` Errors, warnings, logs, or progress written to stdout → stderr. Applies: `print\(|fmt\.Print|echo|console\.log|os\.Stdout|sys\.stdout`. Source: https://clig.dev/#the-basics ("Log messages, errors, and so on should all be sent to stderr ... these messages are displayed to the user and not fed into the next command")
- `CLI-3` Primary or machine-readable output written to stderr, or mixed with decorative text so it cannot be piped → data to stdout, alone. Applies: `stderr|Stderr|>&2|print\(`. Source: https://clig.dev/#the-basics ("The primary output for your command should go to stdout. Anything that is machine readable should also go to stdout")
- `CLI-4` A prompt, `input()`, `read`, or interactive picker with no check that stdin is a TTY and no `--no-input` / flag path → check `isatty` and fail with a message naming the flag. Applies: `input\(|prompt|confirm|readline|\bread\s+-|Scan(ln)?\(|isatty|IsTerminal`. Source: https://clig.dev/#interactivity ("Only use prompts or interactive elements if stdin is an interactive terminal (a TTY) ... in which case a prompt won't work and you should throw an error telling the user what flag to pass")
- `CLI-5` A new destructive action (delete, overwrite, push, drop, bulk update) with no confirmation, and no `--force` / `--yes` path for scripts → prompt when interactive, require `--force` otherwise; offer `--dry-run` for broad changes. Applies: `delete|remove|rm\b|drop|overwrite|truncate|purge|reset|unlink|rmtree|RemoveAll`. Source: https://clig.dev/#arguments-and-flags ("Confirm before doing anything dangerous ... prompt ... if running interactively, or requiring them to pass -f or --force otherwise")
- `CLI-6` A user-supplied value passed to another program as a positional argv entry with no `--` before it → insert `--` so a value starting with `-` is not read as an option. Applies: `exec|subprocess|Command\(|spawn|system\(|\$\{?\w+\}?`. Source: https://pubs.opengroup.org/onlinepubs/9799919799/basedefs/V1_chap12.html#tag_12_02 (Guideline 10: "The first -- argument that is not an option-argument should be accepted as a delimiter indicating the end of options")
- `CLI-7` Shell script that uses unquoted variable expansions, or no `set -e`/`set -u` / explicit status checks → quote `"$var"` and check each command's status. Also check files with a `#!/.*sh` shebang. Files: `**/*.{sh,bash}`. Applies: `\$\w|\$\{`. Source: https://www.gnu.org/software/bash/manual/html_node/The-Set-Builtin.html (`-e` exits on a failing command, `-u` treats unset variables as errors; https://pubs.opengroup.org/onlinepubs/9799919799/utilities/V3_chap02.html#tag_19_06_05 for field splitting of unquoted expansions)
- `CLI-8` A command that expects piped input but reads stdin when stdin is a TTY and no input arg was given → print help or a stderr hint and exit instead of hanging. Applies: `stdin|os\.Stdin|sys\.stdin|read\(`. Source: https://clig.dev/#help ("If your command is expecting to have something piped to it and stdin is an interactive terminal, display help immediately and quit. This means it doesn't just hang")
- `CLI-9` An input or output file argument that does not accept `-` for stdin/stdout → support `-`. Applies: `open\(|os\.(Open|Create)|--(file|input|output)|-o\b|-f\b`. Source: https://clig.dev/#arguments-and-flags ("If input or output is a file, support - to read from stdin or write to stdout"; POSIX Guideline 13)
- `CLI-10` ANSI colors, spinners, or progress bars written without checking TTY, `NO_COLOR`, `TERM=dumb`, and `--no-color` → gate them on those checks, per stream. Applies: `\\x1b|\\033|\\e\[|color|colour|spinner|progress|tqdm|rich\.`. Source: https://clig.dev/#output ("Disable color if your program is not in a terminal or the user requested it"; https://no-color.org/)
- `CLI-11` A renamed or removed flag, subcommand, env var, or changed output format of an existing command → keep the old one with a deprecation warning, or add a new flag. Applies: `add_argument|add_parser|Flag|flag\.|Option\(|@click\.|cobra\.Command|Use:|--\w`. Source: https://clig.dev/#future-proofing ("Keep changes additive where you can ... Warn before you make a non-additive change"; scripts depend on current names and output)
- `CLI-12` Config read in an order other than flags > env > project config > user config > system config → that precedence. Applies: `getenv|environ|os\.Getenv|config|\.env|viper|load_dotenv`. Source: https://clig.dev/#configuration ("Here is the precedence for config parameters, from highest to lowest: Flags, the running shell's environment variables, project-level configuration, user-level configuration, system wide configuration")
- `CLI-13` A per-deploy value (URL, host, bucket, account id, credentials path) hard-coded in the command → read it from env or a flag. Applies: `https?://|\.com\b|localhost|:\d{2,5}\b`. Source: https://12factor.net/config ("strict separation of config from code. Config varies substantially across deploys, code does not")
- `CLI-14` An expected user error (bad path, missing auth, invalid arg) that surfaces as a raw stack trace or a raw library message → catch it and print a one-line message with the fix; keep traces for unexpected errors or `--debug`. Applies: `raise|panic\(|throw|except|err\s*!=\s*nil`. Source: https://clig.dev/#errors ("If you're expecting an error to happen, catch it and rewrite the error message to be useful")
- `CLI-15` A long-running command or cleanup that ignores SIGINT/Ctrl-C, or blocks on cleanup with no second-Ctrl-C escape → exit fast on SIGINT, bound the cleanup, skip it on a second signal. Applies: `signal|SIGINT|SIGTERM|KeyboardInterrupt|Notify\(|trap\b|atexit`. Source: https://clig.dev/#signals ("If a user hits Ctrl-C (the INT signal), exit as soon as possible ... Add a timeout to any clean-up code so it can't hang forever"; also https://clig.dev/#robustness-guidelines "make it crash-only")
- `CLI-16` A new command, flag, or subcommand with no `-h`/`--help` text, or help that goes to stderr / exits non-zero when asked for → help on stdout, exit 0. Applies: `add_argument|add_parser|Flag|flag\.|@click\.|cobra\.Command|usage|--help`. Source: https://www.gnu.org/prep/standards/html_node/_002d_002dhelp.html ("The standard --help option should output brief documentation for how to invoke the program, on standard output, then exit successfully"; https://clig.dev/#help)
- `CLI-17` A subcommand dispatcher that accepts any unambiguous prefix (`mycmd i` for `install`) → exact names plus explicit aliases. Applies: `startswith|HasPrefix|prefix|abbrev|allow_abbrev`. Source: https://clig.dev/#future-proofing ("Don't allow arbitrary abbreviations of subcommands" because a later subcommand makes an old prefix ambiguous; Python argparse `allow_abbrev` https://docs.python.org/3/library/argparse.html#allow-abbrev)
- `CLI-18` (web) A child-process exit status where a signal kill reads as success: `code ?? 0`, `exitCode || 0`, a success test such as `code !== 1`, or a Python `returncode` compared only to a positive value → treat a null code, a signal, or a negative `returncode` as failure. Applies: `exitCode|\bcode\s*(\?\?|\|\|)|on\(['"](exit|close)['"]|returncode|ExitCode\(`. Source: https://github.com/ebernie/kode-review-cli/pull/41 (fix: treat signal exits as failures); https://nodejs.org/api/child_process.html#event-exit (code is null when the child ends by a signal); https://docs.python.org/3/library/subprocess.html#subprocess.Popen.returncode (negative -N means signal N). Confidence: high.
- `CLI-19` (web) A Python CLI that writes output to stdout with no `BrokenPipeError` handling at the entry point → catch `BrokenPipeError`, point stdout at `os.devnull`, and exit quietly, as the Python docs show; do not reset `SIGPIPE` to `SIG_DFL` in a program that also writes to sockets. Without it, `tool | head` ends with a traceback. Files: `**/*.py`. Applies: `print\(|sys\.stdout|__main__`. Source: https://docs.python.org/3/library/signal.html#note-on-sigpipe; https://github.com/igor-ctrl/bcli/pull/13. Confidence: medium.
- `CLI-20` (web) Text from a remote service, a file, or another user printed to the terminal or a pager with no removal of control characters → strip or escape C0/C1 control bytes and ESC sequences (keep newline and tab) before output. An escape sequence in data can rewrite the screen, hide text, or run terminal features. Applies: `print\(|fmt\.(Print|Fprint)|console\.(log|error)|process\.stdout\.write|\becho\b|Pager|pager`. Source: https://github.com/cli/cli/security/advisories/GHSA-3m3g-3wcr-px46 (terminal escape sequence injection in several commands of a popular CLI). Confidence: high.
